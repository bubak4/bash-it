window configuration, or other value.  Pick any character =<c>= for
each binding below.

| =C-x r j <c>=   | =jump-to-register=                 | jump back to the saved position                                                           |
| =C-x r s <c>=   | =copy-to-register=                 | save the region into the register                                                         |
| =C-x r i <c>=   | =insert-register=                  | insert the saved text                                                                     |
| =C-x r w <c>=   | =window-configuration-to-register= | save the current window layout — useful for restoring frames later via =jump-to-register= |
|                 | =view-register=                    | show what a register currently holds                                                      |

** Text navigation and editing

Emacs treats text as a hierarchy: characters → words → sentences →
paragraphs → buffer.  The boundaries of each unit are governed by
major-mode-specific variables (=paragraph-start=, =sentence-end=,
the syntax table) so the same key behaves sensibly in code, prose,
and markup.

*** Built-in editing helpers

**** =shell-command-on-region= (=M-|=)

Pipes the region through a shell command.  With a numeric prefix
argument, the output *replaces* the region; without, it goes into a
temp buffer.  Convenient for in-place reformatting:

1. mark the region
2. =C-1 M-| xmllint --format -=    (the =C-1= prefix triggers replace)

**** =highlight-symbol-query-replace=

Replaces every occurrence of the symbol highlighted by
=highlight-symbol-mode= with a user-supplied replacement.

**** =M-x re-builder=

Build a regexp interactively in a small buffer; matches are
highlighted live in the source buffer.  Aliased to =M-x regexp-builder=.

| =C-c C-w= | =reb-copy= | copy the current regexp to the kill-ring (handy for pasting into =C-M-%=) |

**** Regexp replace (=C-M-%=)

=query-replace-regexp= — interactive search-and-replace using a regex,
with =y/n/!/...= prompting for each match.

**** =rgrep= and =lgrep=

| =M-x rgrep= | recursive grep across files                                   |
| =M-x lgrep= | non-recursive (single directory); shares history with =rgrep= |

Both prompt for a pattern (defaulting to the symbol at point), a file
mask (defaulting to the current buffer's extension), and a top
directory.  They honour =grep-find-ignored-directories= and
=grep-find-ignored-files=.

For project-wide searches, =M-x consult-ripgrep= (=f5 r=) is usually
faster and integrates with the project root.

*** Go to matching parenthesis.

#+BEGIN_SRC emacs-lisp
(defun my/goto-match-paren(arg)
    "Go to the matching parenthesis if on parenthesis otherwise insert '~'."
    (interactive "p")
    (cond ((looking-at "\\s\(") (forward-list 1) (backward-char 1))
        ((looking-at "\\s\)") (forward-char 1) (backward-list 1))
        (t (self-insert-command (or arg 1)))))
#+END_SRC

*** CamelCase to lower_case.  Thanks to Kevin Rodgers <ihs_4664@yahoo.com> for this.

#+BEGIN_SRC emacs-lisp
;; TextFile -> text_file<string>
(defun my/CamelCase-to-lower_case (string)
    (let ((i 0)
             (result "")
             (case-fold-search nil))
        (while (string-match "[[:upper:]][[:lower:]]*" string i)
            (setq result
                (concat result
                    (substring string i (match-beginning 0))
                    (if (> (match-beginning 0) 0) "_")
                    (downcase (match-string 0 string))))
            (setq i (match-end 0)))
        (setq result
            (concat result (substring string i)))))

;; text_file<string> -> TextFile
(defun my/lower_case-to-CamelCase (string)
    (let ((case-fold-search nil))
        (apply #'concat
               (mapcar #'capitalize (split-string string "_" t)))))
#+END_SRC

*** Open terminal with the working directory set to the current buffer's directory or home directory

#+BEGIN_SRC emacs-lisp
;; Define a variable to store the last used directory
(defvar my/last-terminal-directory nil
  "The last directory where a terminal was opened.")

(defun my/open-terminal-in-current-dir (&optional arg)
  "Open terminal in the directory of the current buffer or last used directory.
With universal prefix argument ARG, prompt for directory."
  (interactive "P")
  (let ((dir (cond
              ;; With prefix arg, prompt for directory
              (arg (read-directory-name "Open terminal in directory: " nil nil t))
              ;; Use buffer file directory if available
              ((buffer-file-name) (file-name-directory (buffer-file-name)))
              ;; Use default directory if it exists and is local
              ((and default-directory (not (file-remote-p default-directory))) default-directory)
              ;; Use previously saved directory
              (my/last-terminal-directory my/last-terminal-directory)
              ;; Fall back to home directory
              (t (expand-file-name "~"))))
        (term (if (executable-find "x-terminal-emulator")
                  "x-terminal-emulator"
                (or (executable-find "xterm") nil))))

    ;; Remember this directory for next time
    (setq my/last-terminal-directory dir)

    (if term
        (if (string= term "x-terminal-emulator")
            (start-process "terminal" nil term (concat "--working-directory=" dir))
          ;; For xterm, we use default-directory instead of command line arg
          (let ((default-directory dir))
            (start-process "terminal" nil term)))
      (message "No terminal emulator found."))))
#+END_SRC

*** Project root detection

Shared between =project.el= ([[#project][Project]]) and =projectile= ([[#projectile][Projectile]]).
The list defines the markers that identify a project root and take
precedence over VCS markers like =.git=.  The function turns it into a
=project-find-functions= entry — see the Project section for the
rationale and how it's wired in.

#+BEGIN_SRC emacs-lisp
(defvar my/project-extra-markers
  '(".claude" "CLAUDE.md" ".projectile" ".gitwrapper" ".gitw")
  "Filenames/dirs that mark a project root, prioritised over VCS markers.")

(defun my/project-find-extra-marker (dir)
  "Project root = closest ancestor of DIR containing one of our markers.
Returns a transient project so `project.el' uses the discovered root."
  (when-let* ((root (locate-dominating-file
                     dir
                     (lambda (d)
                       (seq-some
                        (lambda (m) (file-exists-p (expand-file-name m d)))
                        my/project-extra-markers)))))
    (cons 'transient (file-name-as-directory (file-truename root)))))
#+END_SRC

* Claude Code

Integration with the [[https://github.com/manzaltu/claude-code-ide.el][claude-code-ide.el]]
package — an MCP-based bridge between the =claude= CLI and Emacs.
Requires the CLI to be installed and authenticated:

#+BEGIN_SRC sh
npm install -g @anthropic-ai/claude-code
claude --version
claude    # run once interactively to authenticate
#+END_SRC

The package itself is declared in =packages.el=. Use =vterm= as the
terminal backend (cleaner TUI rendering than =eat=). Bind the
transient menu under the existing =f5= prefix.

** Window placement

Claude lives in a *regular* buffer — no side window, no atomic display
rule — so all of Emacs' standard window commands (=C-x 1=, =C-x 2=,
=C-x 0=, =switch-to-buffer=, …) work on it like any other buffer.
=claude-code-ide-use-side-window= is off for the same reason: side
windows survive =delete-other-windows=, which would defeat the
maximize behaviour below.

We also turn off =claude-code-ide-use-ide-diff= so Claude does *not*
launch =ediff=; instead it prints its diff inline inside the terminal.
The package's =ediff= settings are otherwise left at their defaults —
they just go unused.

=f5 i= is a custom toggle: pressing it from another buffer switches to
Claude and maximizes the window (=delete-other-windows=); pressing it
from inside Claude returns to the previous buffer.  After that you're
free to split / rearrange normally.

#+BEGIN_SRC emacs-lisp
(defun my/claude-toggle ()
  "Toggle into / out of the project's Claude Code buffer.
On switch-in the window is maximized via =delete-other-windows=; on
switch-out we just =switch-to-prev-buffer= and let the user manage
windows from there."
  (interactive)
  (let* ((buffer-name (claude-code-ide--get-buffer-name))
         (buffer (get-buffer buffer-name)))
    (cond
     ((null buffer)
      (user-error "No Claude Code session for this project — start one with `f5 a` → `s`"))
     ((eq (current-buffer) buffer)
      (switch-to-prev-buffer))
     (t
      (switch-to-buffer buffer)
      (delete-other-windows)))))

(use-package! claude-code-ide
  :bind (:map my-f5-bindings-keymap
              ("a" . claude-code-ide-menu)   ;; f5 a — full transient (a = AI)
              ("i" . my/claude-toggle))      ;; f5 i — switch in (maximize) / out
  :config
  (setq claude-code-ide-terminal-backend 'vterm
        claude-code-ide-use-side-window  nil   ;; regular window, ediff-friendly
        claude-code-ide-use-ide-diff     nil)  ;; no ediff; inline terminal diff instead

  (claude-code-ide-emacs-tools-setup))
#+END_SRC

** Scrolling inside the Claude buffer

In =vterm-mode= the arrow / page keys are sent to the terminal program,
so you can't normally scroll back through Claude's output.  Use
=vterm-copy-mode=:

| =C-c C-t= | toggle =vterm-copy-mode=. In copy-mode, normal Emacs motion (=C-v=, =M-v=, arrows, =M-<= / =M->=, =isearch=, …) navigates the buffer; press =C-c C-t= or =RET= to drop back into terminal input |

The mouse wheel also scrolls in either mode.

* Project

Treat the following files/directories as authoritative project-root
markers, taking precedence over =.git= and any other VCS markers:

- =.projectile= — projectile's manual project marker
- =.gitwrapper=, =.gitw= — my `gitw` wrapper conventions
- =.claude/=, =CLAUDE.md= — Claude Code project state and instructions

** Why a custom finder (and not just =project-vc-extra-root-markers=)

=project-vc-extra-root-markers= registers extras *at the same level*
as VCS markers: =project.el= walks outward from the buffer and the
**closest** marker wins, regardless of its type.  In a monorepo with
git submodules this means a deeper =.git/= would beat a shallower
=CLAUDE.md= — the opposite of what we want.

The =my/project-find-extra-marker= helper (defined in [[#project-root-detection][Utility
functions › Project root detection]]) is registered in
=project-find-functions= with a very negative depth, so it runs *before*
=project-try-vc=.  If any of our markers is found walking up, that's
the project root; if not, we fall through and =project-try-vc= handles
the buffer with its usual VCS detection.

The order of markers in the list is *not* a priority list — at each
directory walking up we only ask "does this contain any of them".
The first directory with any match wins.

** Implementation

#+BEGIN_SRC emacs-lisp
(after! project
  ;; Run before `project-try-vc' so our markers override .git.
  (add-hook 'project-find-functions #'my/project-find-extra-marker -90))
#+END_SRC

In any buffer inside a project, =M-x project-current= returns
=(transient . "/path/to/root/")= with the discovered root.  Comparing
it with =M-x projectile-project-root= (see [[#projectile][Projectile]]) is a quick
sanity check that both systems agree.

* Projectile

Projectile keeps its own list of root markers in
=projectile-project-root-files-bottom-up=, and unlike =project.el=,
**list order is priority**: each marker is searched independently, and
the first one that finds anything (walking up from the buffer) wins.

Prepending =my/project-extra-markers= (defined in [[#project-root-detection][Utility functions ›
Project root detection]]) to that list gives projectile the same
precedence semantics as the [[#project][Project]] section above — markers like
=CLAUDE.md= take priority over =.git=, even if =.git= is closer to the
buffer.  =delete-dups= keeps the first (our) occurrence of =.projectile=
when projectile's defaults already include it.

#+BEGIN_SRC emacs-lisp
(after! projectile
  (setq projectile-project-root-files-bottom-up
        (delete-dups
         (append my/project-extra-markers
                 projectile-project-root-files-bottom-up))))
#+END_SRC

=M-x projectile-project-root= reports projectile's view of the project
root.  Compare it with =M-x project-current= (see [[#project][Project]]) — for any
buffer in the tree, both should agree after =M-x doom/reload=.

discovered via =project.el=, which honors our

#+BEGIN_SRC emacs-lisp
(defun my/python-activate-project-venv ()
  "Activate `.venv' at the current project root, if one exists.
Uses `project.el' so the same root markers as `claude-code-ide'
and friends apply."
  (when-let* ((proj (project-current))
              (root (project-root proj))
              (venv (expand-file-name ".venv" root)))
    (when (file-directory-p venv)
      (require 'pyvenv)
      (pyvenv-activate venv))))

(add-hook 'python-mode-hook #'my/python-activate-project-venv)

* Vterm

In =vterm-mode= almost every key is captured and forwarded to the
terminal program (e.g. Claude's TUI), so chord sequences like =f5 i=
don't reach Emacs.

Adding =<f5>= to =vterm-keymap-exceptions= isn't enough on its own:
even when the prefix key itself escapes vterm, the *next* key in the
chord (=i=) still hits vterm's =[t]= catch-all and is sent to the
terminal.

Workaround: install the whole =my-f5-bindings-keymap= /
=my-f6-bindings-keymap= as the =<f5>= / =<f6>= prefix in
=vterm-mode-map=.  A major-mode binding wins over the catch-all, so
the chord resolves in our prefix keymap before vterm can grab the
suffix.  Both maps are shared by reference, so any binding added to
them later (=define-key my-f5-bindings-keymap ...=) automatically
works inside vterm too.

#+BEGIN_SRC emacs-lisp
(after! vterm
  (define-key vterm-mode-map (kbd "<f5>") my-f5-bindings-keymap)
  (define-key vterm-mode-map (kbd "<f6>") my-f6-bindings-keymap))
#+END_SRC

* Wgrep

Lets you edit grep / occur / consult-ripgrep result buffers as if
they were the underlying files — perfect for project-wide
search-and-replace.

From inside a grep-style buffer:

| =C-c C-p= | =wgrep-change-to-wgrep-mode= | enter edit mode |

In =wgrep-mode=:

| =C-c C-e= | apply changes back to the file buffers                         |
| =C-c C-u= | unmark all changes (ignore them)                               |
| =C-c C-d= | mark current line for deletion (including its newline)         |
| =C-c C-r= | drop changes inside the region (those changes won't be applied) |
| =C-c C-p= | toggle the read-only area                                      |
| =C-c C-k= | discard everything and exit                                    |
| =C-x C-q= | exit =wgrep-mode=                                              |

When you're done, =M-x wgrep-save-all-buffers= flushes the modified
files to disk.

#+BEGIN_SRC emacs-lisp
(use-package! wgrep)
#+END_SRC

* Whitespace

Show trailing whitespace and strip it on save in text/prog/conf
buffers.

** Why the previous setup stopped working

The old block had three problems:

1. =(setq whitespace-mode 1)= sets a *variable*; it doesn't toggle the
   minor mode.  To enable a mode, you call =(whitespace-mode 1)= or
   =(global-whitespace-mode 1)= — never =setq=.
2. =(after! whitespace ...)= waits for the =whitespace= library to load,
   which doesn't happen until something explicitly requires it.  So the
   body — including the save-hook — typically never ran.
3. =whitespace-style= included =tabs spaces newline empty indentation=,
   which would have highlighted *every* whitespace character, not just
   trailing ones — way too noisy.

Note: Doom's =:editor (whitespace +guess +trim)= module enables
=ws-butler-mode=, which only trims whitespace on lines you have
actually edited.  The setup below is more aggressive — it strips
*all* trailing whitespace on save.  =delete-trailing-whitespace=
runs after =ws-butler= so the net effect is full trim.

** Setup

#+BEGIN_SRC emacs-lisp
(defun my/setup-trailing-whitespace ()
  "Show trailing whitespace and strip it on save in this buffer."
  (setq show-trailing-whitespace t)
  (add-hook 'before-save-hook #'delete-trailing-whitespace nil t))

(add-hook 'text-mode-hook #'my/setup-trailing-whitespace)
(add-hook 'prog-mode-hook #'my/setup-trailing-whitespace)
(add-hook 'conf-mode-hook #'my/setup-trailing-whitespace)
#+END_SRC
